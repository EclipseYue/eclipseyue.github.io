# 多 Agent 协作

多 Agent 系统通过角色分工让多个模型或多个流程协作完成任务。它适合复杂任务，但也会增加调度、成本和不可控性。

## 什么时候需要多 Agent

- 任务天然有多个专业角色。
- 需要并行探索多个方案。
- 需要审查者和执行者相互制衡。
- 单个上下文窗口难以容纳完整任务。

不需要多 Agent 的情况：

- 任务步骤固定且简单。
- 工具调用可以直接完成。
- 结果需要强一致和低延迟。

## 常见架构

- Manager-Worker：管理者分解任务，工作者执行子任务。
- Debate：多个 Agent 提出观点，再由裁判汇总。
- Reviewer：执行 Agent 产出结果，审查 Agent 找问题。
- Specialist Router：根据任务路由到专门 Agent。

## 协作协议

多 Agent 要可靠，需要明确：

- 每个 Agent 的职责。
- 输入输出格式。
- 冲突处理规则。
- 终止条件。
- 共享状态的位置。
- 失败重试策略。

## 风险

- 成本和延迟上升。
- Agent 之间重复工作。
- 错误结论被其他 Agent 放大。
- 调度逻辑复杂，难以调试。

工程上应先从单 Agent 或固定 Workflow 做起，只有复杂度真的需要时再拆多 Agent。
