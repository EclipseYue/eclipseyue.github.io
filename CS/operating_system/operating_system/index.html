    操作系统¶

    课程概述

    本笔记涵盖操作系统的核心概念，包括进程管理、内存管理、文件系统等重要内容。

    1. 操作系统概述¶

    操作系统的定义

    操作系统是管理计算机硬件和软件资源的计算机程序，为用户和应用程序提供服务。

    1.1 操作系统的功能¶

    操作系统的四大基本功能

    1. 处理机管理 - 进程控制、进程同步、进程通信 - CPU调度、时间片分配

    2. 存储器管理 - 内存分配与回收、地址映射 - 虚拟存储管理

    3. 设备管理 - I/O控制、设备分配 - 驱动程序管理

    4. 文件管理 - 文件系统、目录管理 - 文件存取控制

    1.2 操作系统的特征¶

    操作系统的基本特征

    并发性（Concurrency） - 多个程序在同一时间间隔内执行 - 宏观并行，微观串行

    共享性（Sharing） - 系统资源可被多个并发程序共同使用 - 互斥共享和同时共享

    虚拟性（Virtuality） - 通过时间复用和空间复用技术 - 将物理实体变为若干逻辑实体

    异步性（Asynchronism） - 程序执行走走停停，速度不可预知 - 需要同步机制保证程序正确性

    2.进程与线程¶

    2.1 进程与线程¶

    2.1.1 进程的基本概念¶

    进程的引入目的

    为了实现系统的并发性和共享性，操作系统引入了进程的概念。

    进程的组成¶

    进程实体的三个组成部分

    1. PCB（Process Control Block）：进程控制块
    2. 程序段：可执行的程序代码
    3. 数据段：程序运行时的相关数据

    这三部分共同构成进程实体，创建进程实质上就是创建PCB。

    进程的定义¶

    进程的几种典型定义

    • 实例定义：正在执行程序的实例
    • 加载定义：程序及其数据从硬盘加载到内存后在CPU上的执行过程
    • 功能定义：具有独立功能的程序在一个数据集合上运行的过程

    进程的本质

    进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。

    这里的"系统资源"主要指时间资源（时间片）。

    进程的特征¶

    进程的四个基本特征

    1. 动态性（Dynamic） - 进程是程序的一次执行过程，有创建、执行、消亡的过程 - 程序是静态的，进程是动态的

    2. 并发性（Concurrency） - 多个进程可以在同一时间段内执行 - 宏观上同时进行，微观上交替执行

    3. 独立性（Independence） - 进程是能独立运行、独立获得资源、独立接受调度的基本单位 - 不同进程的工作不会相互干扰

    4. 异步性（Asynchronism） - 各进程按各自独立的、不可预知的速度向前推进 - 操作系统必须提供"进程同步机制"来解决异步问题

    2.1.2 进程状态与转换¶

    进程的基本状态

    运行态（Running） - 进程正在CPU上执行 - 单核系统中，同一时刻只有一个进程处于运行态

    就绪态（Ready） - 进程已获得除CPU外的所有必需资源 - 等待分配CPU时间片

    阻塞态（Blocked/Waiting） - 进程因等待某个事件而暂停执行 - 即使给它CPU也无法运行

    状态转换条件

    • 就绪 → 运行：获得CPU时间片
    • 运行 → 就绪：时间片用完
    • 运行 → 阻塞：等待I/O或其他事件
    • 阻塞 → 就绪：等待的事件发生

    2.1.3 进程控制块（PCB）¶

    PCB的重要作用

    PCB是操作系统用于管理和控制进程的数据结构，包含了进程的所有相关信息。

    PCB的主要内容： - 进程标识信息：PID、用户ID等 - 处理机状态信息：寄存器值、程序计数器等 - 进程调度信息：进程状态、优先级等 - 进程控制信息：程序入口地址、资源清单等

    2.1.4 信号机制¶

    信号的概念

    信号是Unix/Linux系统中进程间通信的一种方式，用于通知进程发生了某个事件。

    信号的特点¶

    信号处理特点

    • pending：信号已产生但尚未被处理
    • blocked：信号被暂时阻塞，不会立即处理
    • 优先级：程序号小的信号优先级高
    • 信号丢弃：同类型的后续信号可能被丢弃

    信号相关系统调用¶

    kill系统调用

    C
    int kill(pid_t pid, int sig);
    - 向指定进程发送信号 - pid：目标进程ID - sig：信号编号

    信号处理时机

    • 内核态转用户态时会检查是否有待处理信号
    • 信号可以作为异常处理的配套机制

    常见信号类型¶

    参考CSAPP和man pages中的信号表，了解各种信号的含义和用途。

    2.1.5 线程的引入¶

    为什么引入线程

    为了在进程内部实现更细粒度的并发，提高系统的并发性能。

    进程与线程的关系¶

    资源分配与调度的分离

    • 进程：资源分配的基本单位
    • 线程：CPU调度的基本单位
    • 线程并发：在同一进程内实现多线程并发执行

    线程的优势¶

    线程的特点

    1. 切换开销小 - 线程切换不需要CPU状态切换 - 同一进程内的线程共享地址空间

    2. 资源共享 - 同一进程内的线程共享内存、文件等资源 - 通信更加便捷

    3. 创建销毁快 - 线程的创建和销毁比进程更快

    线程的分类¶

    用户级线程 vs 内核级线程

    用户级线程（User-level Thread） - 由用户程序负责管理，而非操作系统 - 操作系统感知不到用户级线程的存在 - 切换速度快，但无法充分利用多核

    内核级线程（Kernel-level Thread） - 由操作系统内核直接管理 - 可以充分利用多核处理器 - 切换开销相对较大

    用户级线程的限制

    • 一个用户级线程阻塞会导致整个进程阻塞
    • 无法在多核系统上并行执行
    • 调度完全依赖于用户程序的实现

    2.2 CPU调度¶

    2.2.1 调度层次¶

    操作系统中的三级调度

    高级调度（作业调度） - 调度对象：作业 - 功能：从外存后备队列中选择作业调入内存 - 频率：最低

    中级调度（内存调度） - 调度对象：进程 - 功能：将进程调出到外存挂起队列，或从外存调入内存 - 目的：提高内存利用率和系统吞吐量

    低级调度（进程调度/CPU调度） - 调度对象：进程/线程 - 功能：从就绪队列中选取进程分配CPU - 频率：最高，毫秒级

    2.2.2 调度器组成¶

    调度器的三个组成部分

    • 排队器：将新到达的进程插入到相应的队列中
    • 分派器：从就绪队列中选择一个进程分配CPU
    • 上下文切换器：保存当前进程状态，加载新进程状态

    2.2.3 调度时机¶

    需要进行调度的时机

    1. 创建新进程后：需要决定是运行父进程还是子进程
    2. 进程正常终止：必须从就绪队列选择新进程
    3. 进程异常终止：需要重新调度
    4. 进程主动阻塞：如等待I/O操作完成
    5. 时间片用完：时间片轮转调度中
    6. 中断处理完毕：如I/O中断处理完成
    7. 高优先级进程到达：抢占式调度中

    不能进行调度的时机

    1. 处理中断过程中：中断处理必须连续完成
    2. 在内核临界区中：可能导致数据不一致
    3. 原子操作过程中：原语操作不可分割

    2.2.4 调度性能指标¶

    衡量调度算法性能的重要指标

    CPU利用率（CPU Utilization） - CPU忙碌时间的百分比

    系统吞吐量（Throughput） - 单位时间内完成的作业数量

    周转时间（Turnaround Time） - 从作业提交到完成的总时间 - 周转时间 = 完成时间 - 到达时间

    等待时间（Waiting Time） - 进程在就绪队列中等待的总时间

    响应时间（Response Time） - 从提交请求到首次响应的时间

    2.2.5 上下文切换¶

    上下文切换包含的内容

    • 程序计数器（PC）：保存下一条指令的地址
    • 寄存器状态：所有通用寄存器的值
    • 内存管理信息：页表、段表等
    • 进程状态信息：进程ID、优先级等

    2.2.6 调度算法¶

    常用调度算法对比

    算法 思想 可抢占? 优点 缺点 是否饥饿 补充
    FCFS 先来先服务 否 公平，简单 平均等待时间长 否 有利于CPU而非IO
    SJF 短作业优先 否 平均等待时间最短 长作业可能饥饿 是 平均周转时间最短
    SRTF 最短剩余时间优先 是 平均等待时间短 实现复杂，长作业饥饿 是
    高响应比优先 响应比=(等待时间+服务时间)/服务时间 否 兼顾短作业和长作业 计算开销大 否
    时间片轮转 固定时间片循环分配 是 响应时间好，公平 上下文切换开销 否 绝对抢占
    优先级调度 按优先级分配CPU 可选 重要进程优先 低优先级进程饥饿 是
    多级反馈队列 多级队列+反馈机制 是 综合性能好 实现复杂 否 系统开销大

    针对特点但不抢占的算法会饥饿

    详细算法分析¶

    先来先服务（FCFS）

    • 思想：按到达顺序分配CPU
    • 特点：非抢占，公平
    • 缺点：可能出现"护送效应"

    短作业优先（SJF）

    • 思想：优先调度执行时间短的作业
    • 特点：理论上平均等待时间最短
    • 问题：难以预知执行时间，长作业可能饥饿

    高响应比优先调度

    • 公式：响应比 = (等待时间 + 服务时间) / 服务时间
    • 特点：等待时间越长，响应比越高
    • 优势：避免长作业饥饿问题

    时间片轮转（RR）

    • 思想：每个进程分配固定时间片
    • 关键参数：时间片大小的选择
    • 特点：响应时间好，适合交互式系统

    多级反馈队列

    • 设计思想：综合多种调度策略
    • 特点：优先级高的队列时间片小，优先级低的队列时间片大
    • 优势：既照顾短作业，又不会长期忽视长作业
