    数据结构¶

    笔记说明

    这份笔记用于复习考研数据结构内容，参考王道数据结构、陈越数据结构

    ch1. 算法评价¶

    算法的五个重要特性

    1. 输入：算法在执行前需要外界提供0个或多个输入数据
    2. 输出：算法在执行后至少产生一个输出数据
    3. 有穷性：算法必须在执行有限步骤后终止
    4. 确定性：算法的每一步都有确定的含义，不能有歧义
    5. 可行性：算法的每一步都能通过有限的时间和空间来完成

    时间复杂度¶

    时间复杂度增长速度比较

    \[ O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!) < O(n^n) \]

    复杂度分析题目（2022年）

    C
    int sum = 0;
for (int i = 1; i < n; i *= 2)      // 外层循环执行 log₂n 次
    for (j = 0; j < i; j++)         // 内层循环执行 i 次
        sum++;

    分析过程：

    • 外层循环：i 依次为 1, 2, 4, 8, ..., n/2（约 log₂n 次）
    • 内层循环总执行次数：1 + 2 + 4 + 8 + ... + n/2 = n - 1
    • 时间复杂度：O(n)

    ch2. 线性表¶

    线性表定义

    具有相同数据类型的n个数据元素的有限序列，记作 L = (a₁, a₂, ..., aₙ)

    2.1 基本操作¶

    线性表基本操作

    1. InitList(&L) - 初始化线性表
    2. Length(L) - 求表长
    3. LocateElem(L, e) - 按值查找
    4. GetElem(L, i) - 按位查找
    5. ListInsert(&L, i, e) - 插入操作
    6. ListDelete(&L, i, &e) - 删除操作
    7. PrintList(L) - 输出操作
    8. Empty(L) - 判空操作
    9. DestroyList(&L) - 销毁操作

    2.2 顺序表¶

    顺序表特点

    一组地址连续的存储单元依次存储线性表中的数据元素，实现逻辑相邻 = 物理相邻

    优缺点对比：

    优点 缺点
    存储密度高，随机存取 插入删除需要移动大量元素
    访问速度快 空间利用率不高

    顺序表操作复杂度

    操作 最好情况 最坏情况 平均情况
    插入 O(1) O(n) O(n)
    删除 O(1) O(n) O(n)
    查找 O(1) O(n) O(n)
    按位访问 O(1) O(1) O(1)

    2.3 链表¶

    链表结构定义

    使用data|next结构存储线性表中的数据元素

    C
    typedef struct LNode {
    ElemType data;          // 数据域
    struct LNode *next;     // 指针域
} LNode, *LinkList;

    链表特性：

    链表特点

    • 非随机存取：必须从头结点开始遍历
    • 离散存储：结点在内存中不连续
    • 动态分配：可在运行时动态调整大小
    • 头结点：便于统一处理（可选）

    链表基本操作¶

    链表初始化（带头结点）

    C
    bool InitList(LinkList &L) {
    L = (LNode *)malloc(sizeof(LNode));  // 分配头结点
    if (L == NULL) return false;         // 内存不足，分配失败
    L->next = NULL;                      // 头结点指针域置空
    return true;
}

    插入操作技巧

    • 前插法：需要找到第i-1个结点p
    • 后插法：可以直接通过第i个结点p执行插入（将新结点插入到p后面，然后交换数据）

    特殊链表¶

    双向链表

    C
    typedef struct DNode {
    ElemType data;
    struct DNode *prior, *next;    // 前驱和后继指针
} DNode, *DLinkList;

    循环链表

    • 单向循环：尾结点的next指向头结点
    • 双向循环：头结点的prior指向尾结点，尾结点的next指向头结点

    静态链表

    C
    typedef struct {
    ElemType data;
    int next;              // 下一个元素的数组下标
} SLinkList[MAXSIZE];
    • 用数组模拟链表，适用于不支持指针的语言
    • next == -1 作为结束标志

    ch3. 栈、队列和数组¶

    3.1 栈¶

    栈的定义

    LIFO（Last In First Out，后进先出）的线性数据结构，只能在栈顶进行插入和删除操作

    栈的基本操作

    1. InitStack(&S) - 初始化栈
    2. StackEmpty(S) - 判断栈是否为空
    3. Push(&S, e) - 入栈
    4. Pop(&S, &e) - 出栈
    5. GetTop(S, &e) - 读栈顶元素
    6. DestroyStack(&S) - 销毁栈

    卡特兰数

    n个不同元素进栈时，出栈元素的不同排列数为： $\(C_n = \frac{1}{n+1} \binom{2n}{n}\)$

    3.1.1 顺序栈¶

    顺序栈实现

    C
    typedef struct {
    ElemType data[MAXSIZE];
    int top;                // 栈顶指针，初始值为-1
} SqStack;

// 判空条件：top == -1
// 判满条件：top == MAXSIZE-1

    共享栈

    两个栈共享一个数组空间，提高内存利用率

    Text Only
    0                       MAXSIZE-1
|       |       |       |
bottom0 top0    top1   bottom1
    • top0 从左向右增长，top1 从右向左增长
    • 栈满条件：top0 + 1 == top1

    3.1.2 链式栈¶

    链式栈实现

    C
    typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkStack;
    • 栈顶指针指向链表头部
    • 无栈满问题，只要内存足够

    3.2 队列¶

    队列定义

    FIFO（First In First Out，先进先出）的线性数据结构，在队尾插入，在队头删除

    C
    typedef struct {
    ElemType data[MAXSIZE];
    int front, rear;        // 队头和队尾指针
} SqQueue;

    队列基本操作

    1. InitQueue(&Q) - 初始化队列
    2. QueueEmpty(Q) - 判断队列是否为空
    3. EnQueue(&Q, e) - 入队
    4. DeQueue(&Q, &e) - 出队
    5. GetHead(Q, &e) - 读队头元素
    6. DestroyQueue(&Q) - 销毁队列

    循环队列¶

    循环队列的关键问题

    如何区分队空和队满？三种解决方案：

    方案一：牺牲一个存储单元

    C
    // 队空条件：front == rear
// 队满条件：(rear + 1) % MAXSIZE == front
// 元素个数：(rear - front + MAXSIZE) % MAXSIZE

    方案二：增加size变量

    C
    typedef struct {
    ElemType data[MAXSIZE];
    int front, rear, size;
} SqQueue;

// 队空条件：size == 0
// 队满条件：size == MAXSIZE

    方案三：增加tag标志

    C
    typedef struct {
    ElemType data[MAXSIZE];
    int front, rear, tag;
} SqQueue;

// 队满：插入导致 rear == front 时置 tag = 1
// 队空：删除导致 front == rear 时置 tag = 0

    链式队列¶

    链式队列实现

    C
    typedef struct LinkNode {
    ElemType data;
    struct LinkNode *next;
} LinkNode;

typedef struct {
    LinkNode *front, *rear;    // 队头和队尾指针
} LinkQueue;

    链式队列特点

    • 通常使用带头结点的单链表
    • 不存在队满问题
    • 入队在rear端，出队在front端

    双端队列¶

    双端队列（deque）

    • 定义：可以在队头和队尾进行插入和删除操作
    • 输入受限的双端队列：只能在一端进行插入操作
    • 输出受限的双端队列：只能在一端进行删除操作

    3.3 栈和队列的应用¶

    应用场景

    • 栈：表达式求值、括号匹配、函数调用、递归实现
    • 队列：层次遍历、缓冲区、打印队列、广度优先搜索

    4.3 KMP算法¶

    算法背景

    解决字符串模式匹配问题，避免暴力匹配中的重复比较

    4.3.1 基本思想¶

    算法比较

    • 暴力匹配：主串和模式串逐字符比较，时间复杂度 O(mn)
    • KMP算法：利用模式串的"最长相等前后缀"信息，时间复杂度 O(m+n)

    4.3.2 next数组¶

    next数组的作用

    在模式串失配时，指示下一个比较位置，避免主串指针回溯

    计算规则

    • next[j] 表示模式串 T[1..j] 的最长相等前后缀长度
    • 失配时，j 跳转到 next[j] 位置继续比较

    4.3.3 代码实现¶

    next数组求解

    C
    void get_next(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;                    // 单个字符的最长前后缀长度为0

    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            ++i; ++j;
            next[i] = j;            // 匹配成功，长度加1
        } else {
            j = next[j];            // 失配，j回退
        }
    }
}

    KMP主算法

    C
    int Index_KMP(SString S, SString T, int pos, int next[]) {
    int i = pos, j = 1;             // i指向主串，j指向模式串

    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {
            ++i; ++j;               // 匹配成功，继续比较下一个
        } else {
            j = next[j];            // 失配，模式串指针回退
        }
    }

    if (j > T.length)               // 匹配成功
        return i - T.length;
    else
        return 0;                   // 匹配失败
}

    4.3.4 算法优化¶

    nextval数组优化

    当 T[j] == T[next[j]] 时，可以直接跳转到 nextval[j] = nextval[next[j]]，进一步减少比较次数

    算法总结

    • KMP通过next数组实现高效匹配，避免重复回溯
    • next数组的核心是利用模式串的前缀信息
    • 时间复杂度：O(m+n)，空间复杂度：O(m)

    ch5. 树与二叉树¶

    5.1 树的基本概念¶

    树的定义

    树是一个非线性数据结构，由结点和边组成，满足以下性质：

    • 有且仅有一个根结点
    • 当n>1时，其余结点可分为m(m>0)个互不相交的有限集T₁,T₂,...,Tₘ，称为根的子树

    树的特点

    1. 树的根节点没有前驱，除根节点外的所有结点有且只有一个前驱
    2. 每个结点有0个或多个后继结点
    3. 在n个结点的树中，有且仅有n-1条边

    基本术语¶

    结点关系术语

    • 祖先（ancestor）：从根到该结点路径上的所有结点
    • 子孙（descendant）：以该结点为根的子树中的所有结点
    • 兄弟（sibling）：具有相同双亲的结点
    • 堂兄弟（cousin）：双亲在同一层的结点

    结点分类术语

    • 结点的度：树的一个结点的孩子个数
    • 树的度：树中结点的最大度数
    • 分支结点（branch node）：又叫非终端结点，度大于0的结点
    • 叶结点（leaf node）：度为0的结点，又称终端结点

    层次相关术语

    术语 定义 说明
    结点的层次 根结点为第1层，其子结点为第2层... 从1开始计数
    结点的深度 从根结点到该结点的路径长度 根结点深度为0
    结点的高度 以该结点为根的子树的高度 叶结点高度为0
    树的高度 树中结点的最大层数 等于根结点的高度+1

    其他重要术语

    • 有序树：结点的子树从左到右有顺序，不能交换
    • 无序树：结点的子树没有顺序要求
    • 路径：从一个结点到另一个结点经过的结点序列
    • 路径长度：路径上边的个数
    • 森林：m(m≥0)棵互不相交的树的集合

    树的性质¶

    树的重要性质

    性质1： 结点数与边数关系

    树中结点数 = 所有结点的度数之和 + 1

    性质2： m叉树第i层结点数上界

    度为m的树中第i层至多有 \(m^{i-1}\) 个结点（i≥1）

    性质3： m叉树结点总数上界

    高度为h的m叉树至多有 \(\frac{m^h - 1}{m - 1}\) 个结点

    高度计算公式

    性质4： m叉树最小高度

    度为m、具有n个结点的树的最小高度为： $\(h = \lceil \log_m(n(m-1)+1) \rceil\)$

    性质5： m叉树最大高度

    度为m、具有n个结点的树的最大高度为：\(h = n - m + 1\)

    性质应用举例

    对于一棵有100个结点的三叉树：

    • 最小高度：\(h = \lceil \log_3(100 \times 2 + 1) \rceil = \lceil \log_3(201) \rceil = 5\)
    • 最大高度：\(h = 100 - 3 + 1 = 98\)

    5.2 二叉树¶

    二叉树定义

    二叉树是一种特殊的树形结构，其特点是每个节点至多只有两棵保持左右顺序的子树。

    二叉树和度为2的有序树的区别

    • 度为2的树至少有3个结点，而二叉树可以为空
    • 度为2的有序树的孩子的左右次序是相对于另一个孩子而言的，而二叉树的左右子树是相对于父节点而言的

    Info

    • 满二叉树: 高度为h，且有 \(2^h - 1\) 个结点的二叉树，层序编号后，对于编号为i的结点，其左孩子编号为2i，右孩子编号为2i+1，其父亲编号为i/2（向下取整）。
    • 完全二叉树: 高度为h，有n个结点的二叉树，当且仅当其每个结点都与满二叉树的结点一一对应时，称为完全二叉树。完全二叉树的特点是从左到右依次填充结点，最后一层可能不满。
    • 若i <= n/2(向下取整)，则结点i为分支结点，否则为叶结点。
    • 叶结点只可能在层次最大的两层上出现，对于最大层次的叶结点，都依次排列在该层最左边的位置上。
    • 若有度为1的结点，则最多只可能有一个，且该节点只有左孩子而无右孩子。
    • 按层序编号后，一旦出现某结点（编号为i）为叶结点或只有左孩子，则编号大于i的结点均为叶结点。
    • 若n为奇数，则每个分支结点都有左孩子和右孩子，若n为偶数，则编号最大的分支结点(编号为n/2)只有左孩子而无右孩子。
    • 正则二叉树：树中每个分支结点都有2个孩子，即树中只有度为0或2的结点。

    二叉树的性质

    • 性质1: 非空二叉树上的叶结点数等于度为2的结点数加1，即 $$ n_0 = n_2 + 1 $$ 其中n₀为叶结点数，n₂为度为2的结点数。(通过入度证明)
    • 性质2: 非空二叉树的第k层最多有2^(k-1)个结点(k≥1)。
    • 性质3: 高度为h的二叉树至多有 \(2^h - 1\) 个结点(h≥1)。
    • 性质4: 对完全二叉树按层序编号，有以下关系:
    • 若i<=n/2(向下取整)，则结点i为分支结点，否则为叶结点，即最后一个分支结点的编号为n/2(向下取整)。
    • 叶结点只可能在层次最大的两层上出现。
    • 若有度为1的结点，则最多只可能有一个，且该节点只有左孩子而无右孩子。
    • 按层序编号后，一旦出现某结点（编号为i）为叶结点或只有左孩子，则编号大于i的结点均为叶结点。
    • 若n为奇数，则每个分支结点都有左孩子和右孩子，若n为偶数，则编号最大的分支结点(编号为n/2)只有左孩子而无右孩子。
    • 当i > 1时，结点i的双亲结点编号为i/2（向下取整）。
    • 若结点i有左右孩子，则左孩子编号为2i，右孩子编号为2i+1。
    • 结点i所在层次为k，则k = log₂i(向下取整) + 1。
    • 性质5: 二叉树的高度h与结点数n的关系为 $$ h = \lceil \log_2(n + 1) \rceil $$ 或者 $$ h = \lceil \log_2(n) + 1 \rceil $$ 其中n为结点数。

    二叉树的存储结构

    二叉树存储结构

    二叉树的存储结构主要有两种：顺序存储和链式存储。

    • 顺序存储: 采用数组存储二叉树，适用于完全二叉树。通过层序遍历将结点按顺序存入数组，空缺位置用NULL填充。优点是存取方便，缺点是浪费空间。
    • 链式存储: 采用链表存储二叉树，每个结点包含数据域和左右孩子指针。适用于稀疏树，优点是节省空间，缺点是存取较慢。

    5.3 二叉树的遍历¶

    二叉树遍历

    二叉树的遍历是指按照一定的顺序访问二叉树的所有结点。

    遍历方式

    • 前序遍历: 根结点 -> 左子树 -> 右
    • 中序遍历: 左子树 -> 根结点 -> 右子树
    • 后序遍历: 左子树 -> 右子树 -> 根
    • 层序遍历: 按层次从上到下、从左到右访问结点

    前中后可以理解为根被遍历到的顺序

    对于手写遍历，想象从根节点从上到下、从左到右环绕树，然后前序中序后序分别在左中右三个位置有标记，按照碰到标记的顺序作为顺序。

    前三种对应的递归算法如下:

    C
    void PreOrder(BiTree T) {
    if (T != NULL) {
        visit(T);  // 访问根结点
        PreOrder(T->lchild);      // 递归访问左子树
        PreOrder(T->rchild);      // 递归访问右子树
    }
}

void InOrder(BiTree T) {
    if (T != NULL) {
        InOrder(T->lchild);      // 递归访问左子树
        visit(T);  // 访问根结点
        InOrder(T->rchild);      // 递归访问右子树
    }
}

    if (T != NULL) {
        PostOrder(T->lchild);    // 递归访问左子树
        PostOrder(T->rchild);    // 递归访问右子树
        visit(T);  // 访问根结点
    }
}

    线索二叉树¶

    线索二叉树的概念

    利用二叉树中的空指针域，存放指向该结点在某种遍历次序下的前驱和后继结点的指针。

    基本思想： 在含有n个结点的二叉树中，有n+1个空指针域，可以利用这些空指针存放前驱或后继的线索。

    结点结构：

    C
    typedef struct ThreadNode {
    ElemType data;                     // 数据域
    struct ThreadNode *lchild, *rchild; // 左右孩子指针
    int ltag, rtag;                    // 左右线索标志
} ThreadNode, *ThreadTree;

    标志位说明： - ltag = 0：lchild指向左孩子；ltag = 1：lchild指向前驱 - rtag = 0：rchild指向右孩子；rtag = 1：rchild指向后继

    中序线索二叉树¶

    构造过程：

    C
    // 中序线索化递归函数
void InThread(ThreadTree &p, ThreadTree &pre) {
    if (p != NULL) {
        InThread(p->lchild, pre);        // 递归线索化左子树

        if (p->lchild == NULL) {         // 左子树为空，建立前驱线索
            p->ltag = 1;
            p->lchild = pre;
        }
        if (pre != NULL && pre->rchild == NULL) { // 建立后继线索
            pre->rtag = 1;
            pre->rchild = p;
        }
        pre = p;                         // 更新前驱结点

        InThread(p->rchild, pre);        // 递归线索化右子树
    }
}

// 主函数
void CreateInThread(ThreadTree &T) {
    ThreadTree pre = NULL;
    if (T != NULL) {
        InThread(T, pre);
        if (pre->rchild == NULL) {       // 处理最后一个结点
            pre->rtag = 1;
        }
    }
}

        visit(p);
}

    先序和后序线索化特点

    先序线索二叉树： - 后继查找：有左孩子则后继为左孩子，否则为右孩子，叶结点的后继由线索指出 - 前驱查找：较复杂，通常在线索化过程中处理

    后序线索二叉树： - 后继查找规则： 1. 若为根结点，后继为空 2. 若为双亲的右孩子，或为双亲的左孩子且双亲无右子树，后继为双亲 3. 若为双亲的左孩子且双亲有右子树，后继为双亲右子树中后序遍历的第一个结点

    树、森林与二叉树的转换¶

    转换规则

    树转二叉树：(左孩子右兄弟) 1. 加线：在所有兄弟结点之间加一条连线 2. 去线：树中每个结点，只保留与第一个孩子结点的连线，删除与其他孩子的连线 3. 层次调整：以树的根结点为轴心，将整棵树顺时针旋转一定角度

    森林转二叉树： 1. 把每棵树转换为二叉树 2. 第一棵二叉树不动，其余二叉树依次作为前一棵二叉树根结点的右子树

    二叉树转树或森林： 1. 若二叉树非空，则根结点的右子树为森林，左子树为第一棵树 2. 按照树转二叉树的逆过程进行

    树和森林的遍历¶

    树的遍历： - 先根遍历：先访问根结点，再依次遍历各子树 - 后根遍历：先依次遍历各子树，再访问根结点

    森林的遍历： - 先序遍历：依次对森林中每棵树进行先根遍历 - 中序遍历：依次对森林中每棵树进行后根遍历

    遍历等价性

    • 树的先根遍历 ≡ 对应二叉树的先序遍历
    • 树的后根遍历 ≡ 对应二叉树的中序遍历
    • 森林的先序遍历 ≡ 对应二叉树的先序遍历
    • 森林的中序遍历 ≡ 对应二叉树的中序遍历

    5.5 哈夫曼树和哈夫曼编码¶

    基本概念

    • 路径长度：从树中一个结点到另一个结点之间的分支数目
    • 结点的权：给每个结点赋予的一个有意义的数值
    • 结点的带权路径长度：从根结点到该结点之间的路径长度与该结点权的乘积
    • 树的带权路径长度（WPL）：树中所有叶结点的带权路径长度之和

    哈夫曼树（最优二叉树）： 在含有n个带权叶结点的二叉树中，带权路径长度最小的二叉树。

    哈夫曼树的构造¶

    哈夫曼算法

    1. 初始化：由给定的n个权值构成n棵只有根结点的二叉树，得到森林F
    2. 选取和合并：在F中选取两棵根结点权值最小的树作为左右子树，构造一棵新的二叉树，新树根结点权值为左右子树权值之和
    3. 删除和加入：从F中删除被选取的两棵树，把新构造的树加入F中
    4. 重复步骤2-3，直到F中只剩一棵树为止

    算法实现：

    C
    typedef struct {
    int weight;                         // 权值
    int parent, lch, rch;               // 双亲、左孩子、右孩子下标
} HTNode, *HuffmanTree;

void CreateHuffmanTree(HuffmanTree &HT, int *w, int n) {
    if (n <= 1) return;
    int m = 2 * n - 1;                  // 哈夫曼树总结点数
    HT = new HTNode[m + 1];             // 0号单元未用

    // 初始化
    for (int i = 1; i <= m; ++i) {
        HT[i].parent = HT[i].lch = HT[i].rch = 0;
    }
    for (int i = 1; i <= n; ++i) {
        HT[i].weight = w[i-1];
    }

    // 构造哈夫曼树
    for (int i = n + 1; i <= m; ++i) {
        int s1, s2;
        Select(HT, i - 1, &s1, &s2);   // 选择权值最小的两个结点
        HT[s1].parent = HT[s2].parent = i;
        HT[i].lch = s1; HT[i].rch = s2;
        HT[i].weight = HT[s1].weight + HT[s2].weight;
    }
}

    • 哈夫曼编码是最优前缀编码，即平均编码长度最短

    ch6. 图¶

    6.1 图的基本概念¶

    图的定义

    图是由顶点集合V和边集合E组成的数据结构，记作G(V,E)，用于表示多对多的关系。

    6.2 图的存储结构¶

    6.2.1 邻接矩阵¶

    邻接矩阵表示法

    使用二维数组存储图中顶点之间的邻接关系。

    无向图/有向图： 不连通用0填充 带权图： 不连通用∞填充

    时间复杂度： O(|V|²) 空间复杂度： O(|V|²)

    邻接矩阵特点

    • 适合稠密图
    • 判断两顶点是否相邻：O(1)
    • 找某顶点的所有邻接点：O(|V|)

    6.2.2 邻接表¶

    邻接表表示法

    使用链表存储每个顶点的邻接顶点，通常采用头插法。

    • 存储内容： 邻接顶点的下标
    • 无向图： 每条边在两个顶点的邻接表中都出现
    • 次序： 不唯一，取决于插入顺序

    邻接表特点

    • 适合稀疏图
    • 空间复杂度：O(|V|+|E|)
    • 找某顶点的邻接点：O(度数)

    6.3 图的遍历¶

    6.3.1 广度优先搜索（BFS）¶

    BFS基本思想

    从某个顶点开始，先访问其所有邻接顶点，再访问这些邻接顶点的邻接顶点，类似于树的层序遍历。

    BFS算法实现思路

    1. 初始化所有顶点为未访问状态
    2. 从顶点0开始，对每个未访问顶点调用BFS
    3. BFS过程： - 将起始顶点入队并标记为已访问 - 循环：出队一个顶点，将其所有未访问的邻接顶点入队并标记 - 直到队列为空

    复杂度分析：

    BFS时间复杂度

    • 邻接表： O(|V|+|E|)
    • 邻接矩阵： O(|V|²)

    BFS应用

    单源最短路径（无权图）： 每次访问邻接顶点时距离+1，最先到达的路径即为最短路径

    6.3.2 深度优先搜索（DFS）¶

    DFS基本思想

    从某个顶点开始，沿着一条路径一直走到底，然后回溯到上一个顶点，继续探索其他路径。

    DFS算法实现思路

    1. 对每个未访问顶点调用DFS
    2. DFS过程： - 标记当前顶点为已访问 - 选择一个未访问的邻接顶点递归调用DFS - 回溯到当前顶点，继续探索其他邻接顶点

    复杂度分析：

    DFS时间复杂度

    • 邻接表： O(|V|+|E|)
    • 邻接矩阵： O(|V|²)

    6.3.3 遍历应用¶

    连通性判断

    图的遍历算法可以判断图的连通性：一次遍历能访问所有顶点，则图连通

    6.4 最小生成树¶

    最小生成树定义

    连通加权无向图中，权值和最小的生成树。

    6.4.1 基本性质¶

    最小生成树性质

    1. 边数： n个顶点的MST恰好有n-1条边
    2. 唯一性： 如果边权都不相同，MST唯一
    3. 权值和： 最小且唯一
    4. 路径： MST中未必包含任意两点间的最短路径

    6.4.2 构造算法的基本思想¶

    MST构造的通用算法

    Text Only
    GENERIC_MST(G){
    T = ∅;
    while T未形成一棵生成树:
        找到一条最小代价边(u,v)且加入T后不会产生回路;
        T = T ∪ {(u,v)}
}

    6.4.3 Prim算法¶

    Prim算法（加点法）

    从一个顶点开始，逐步加入与当前树相邻的最小权值边对应的顶点。

    Text Only
    void Prim(G, T){
    T = ∅;
    U = {w};  // 任选一个起始顶点
    while((V-U) ≠ ∅){
        设(u,v)是使u∈U, v∈(V-U)，且权值最小的边;
        T = T ∪ {(u,v)};
        U = U ∪ {v};
    }
}

    Prim算法特点

    • 时间复杂度： O(|V|²)
    • 适用场景： 稠密图
    • 实现： 通常用优先队列优化

    6.4.4 Kruskal算法¶

    Kruskal算法（加边法）

    将所有边按权值排序，依次选择最小边，若不形成回路则加入MST。

    Text Only
    void Kruskal(V, T){
    T = V;  // 初始时每个顶点自成连通分量
    numS = n;
    while(numS > 1){
        从E中取出权值最小的边(v,u);
        if(v和u属于T中不同的连通分量){
            T = T ∪ {(v,u)};
            numS--;
        }
    }
}

    Kruskal算法特点

    • 时间复杂度： O(|E|log|E|)
    • 适用场景： 稀疏图
    • 关键技术： 并查集判断连通性

    6.5 最短路径¶

    6.5.1 Dijkstra算法¶

    Dijkstra算法

    求解单源最短路径问题，适用于非负权图。

    Dijkstra算法步骤

    1. 初始化： S = {0}, dist[i] = arcs[0][i]
    2. 选择： 从V-S中选出dist值最小的顶点vⱼ，S = S ∪ {j}
    3. 更新： 对V-S中的每个顶点vₖ，如果dist[j]+arcs[j][k] < dist[k]， 则更新dist[k] = dist[j] + arcs[j][k]
    4. 重复： 执行步骤2-3共n-1次

    Dijkstra算法限制

    • 时间复杂度： O(|V|²)（邻接矩阵）
    • 不支持负权边
    • 适用于求单源最短路径

    6.5.2 Floyd算法¶

    Floyd算法

    求解所有顶点对之间的最短路径问题。

    Floyd算法思想

    通过动态规划，依次考虑以每个顶点作为中转点的最短路径。

    Text Only
    for(k = 0; k < n; k++)      // 中转点
    for(i = 0; i < n; i++)  // 起点
        for(j = 0; j < n; j++)  // 终点
            if(dist[i][k] + dist[k][j] < dist[i][j])
                dist[i][j] = dist[i][k] + dist[k][j];

    Floyd算法特点

    • 时间复杂度： O(|V|³)
    • 允许负权边（但不允许负权回路）
    • 适用于稠密图
    • 可以处理有向图和无向图

    6.6 拓扑排序¶

    拓扑排序定义

    对有向无环图(DAG)的顶点进行线性排序，使得对于任何有向边(u,v)，u在排序中都出现在v之前。

    拓扑排序算法

    1. 计算所有顶点的入度
    2. 将入度为0的顶点入队
    3. 循环： - 出队一个顶点，输出它 - 将该顶点的所有邻接顶点的入度减1 - 若某邻接顶点入度变为0，则入队
    4. 直到队列为空

    拓扑排序应用

    • AOV网：顶点表示活动，边表示活动间的优先关系
    • 检测回路：若不能输出所有顶点，则图中存在回路
    • 编译依赖：确定编译顺序

    6.7 关键路径¶

    AOE网（Activity On Edge）

    用边表示活动、顶点表示事件的有向无环图，用于项目调度分析和工程管理。

    6.7.1 基本概念¶

    AOE网与AOV网对比

    特征 AOV网 AOE网
    顶点含义 活动 事件
    边的含义 优先关系 活动
    应用 拓扑排序 关键路径
    目标 确定活动顺序 找到项目瓶颈

    重要术语

    • 事件：表示在它之前的活动已经完成，在它之后的活动可以开始
    • 活动：消耗时间的工序，用有向边表示
    • 路径长度：路径上各活动持续时间之和
    • 关键路径：从源点到汇点的最长路径

    6.7.2 关键路径算法¶

    计算步骤¶

    关键路径求解步骤

    第一步：拓扑排序 - 求出所有顶点的拓扑序列

    第二步：求事件的最早发生时间ve[i] - 按拓扑顺序计算，前向取最大值 - ve[i] = max{ve[k] + <k,i>的权值}

    第三步：求事件的最迟发生时间vl[i] - 按逆拓扑顺序计算，后向取最小值 - vl[i] = min{vl[k] - <i,k>的权值}

    第四步：求活动的最早开始时间e[i] - 活动的最早开始时间：e[i] = ve[j]

    第五步：求活动的最迟开始时间l[i] - 活动的最迟开始时间：l[i] = vl[k] - <j,k>的权值

    第六步：计算时间余量 - 活动的时间余量：d[i] = l[i] - e[i] - 关键活动：时间余量为0的活动

    关键路径特点

    • 关键路径是从源点到汇点的最长路径
    • 关键路径上的所有活动都是关键活动
    • 关键活动的时间余量为0
    • 缩短关键活动的时间可以缩短整个工程的工期

    6.7.3 算法实现要点¶

    实现关键

    事件时间计算： - ve[i]：按拓扑顺序，从前往后，取最大值 - vl[i]：按逆拓扑顺序，从后往前，取最小值

    活动时间计算： - e[i] = ve[起点]（活动从起点事件开始） - l[i] = vl[终点] - 活动持续时间（活动必须在终点事件前完成）

    关键路径识别： - 时间余量 d[i] = l[i] - e[i] = 0 的活动构成关键路径

    注意事项

    • 一个AOE网可能有多条关键路径
    • 只有缩短所有关键路径上的活动时间，才能缩短工程总工期
    • 关键路径可能会因为某些活动时间的改变而发生变化

    6.7.4 应用意义¶

    关键路径的实际应用

    项目管理： - 确定项目的最短完成时间 - 识别项目中的关键环节 - 合理分配资源，重点关注关键活动

    工程调度： - 优化工程进度安排 - 找出可能延误整个工程的瓶颈活动 - 为赶工提供决策依据

    ch7. 查找¶

    查找的基本概念

    平均查找长度（ASL）：在查找过程中，关键字的平均比较次数，是衡量查找算法效率的主要指标。

    7.1 线性查找¶

    7.1.1 顺序查找¶

    顺序查找特点

    • 适用范围：有序表和无序表都可以使用
    • 时间复杂度：O(n)
    • 空间复杂度：O(1)

    7.1.2 折半查找（二分查找）¶

    折半查找的前提条件

    只能用于有序的顺序表

    折半查找性能分析

    • 时间复杂度：O(log₂n)
    • 平均查找长度：ASL = log₂(n+1) - 1
    • 判定树高度：h = ⌈log₂(n+1)⌉

    7.1.3 分块查找¶

    分块查找的特点

    结合了顺序查找和折半查找的优点，适用于分块有序的数据。

    7.2 树表查找¶

    7.2.1 二叉排序树（BST）¶

    二叉排序树的性质

    • 若左子树不空，则左子树上所有结点的值均小于根结点的值
    • 若右子树不空，则右子树上所有结点的值均大于根结点的值
    • 左、右子树也分别为二叉排序树

    7.2.2 平衡二叉树（AVL）¶

    AVL树的特点

    • 平衡因子：|左子树高度 - 右子树高度| ≤ 1
    • 查找复杂度：O(log n)
    • 目标：实现更好的查找性能
    旋转操作¶

    AVL树的旋转规则

    基本旋转： - 右旋：当冲突结点的右孩子变为左孩子时使用 - 左旋：当冲突结点的左孩子变为右孩子时使用

    旋转目的：保证中序遍历序列不变，但降低树的高度

    失衡调整¶

    四种失衡情况的处理

    LL型失衡：失衡结点BF=2，左孩子BF=1 - 处理方法：对失衡结点进行右旋

    RR型失衡：失衡结点BF=-2，右孩子BF=-1 - 处理方法：对失衡结点进行左旋

    LR型失衡：失衡结点BF=2，左孩子BF=-1 - 处理方法：先左旋左孩子，再右旋失衡结点

    RL型失衡：失衡结点BF=-2，右孩子BF=1 - 处理方法：先右旋右孩子，再左旋失衡结点

    失衡调整原则

    当多个祖先结点失衡时，只需调整距离插入点最近的失衡结点。

    7.2.3 红黑树¶

    红黑树的性质

    1. 左根右：保持二叉排序树的性质
    2. 根叶黑：根结点和叶结点（NIL）都是黑色
    3. 不红红：红结点的孩子必须是黑色
    4. 黑路同：从根到叶的所有路径上黑结点数目相同

    红黑树的优势

    • 查找复杂度：O(log n)
    • 高度保证：h ≤ 2log₂(n+1)
    • 性能稳定：保证最长路径不超过最短路径的2倍
    插入调整¶

    红黑树插入策略

    插入红色结点： - 如果不违反性质，无需调整 - 如果违反性质，按情况处理：

    情况1：插入根结点 - 直接变为黑色

    情况2：叔结点为红色 - 叔父爷三结点变色，将爷结点作为新插入结点向上调整

    情况3：叔结点为黑色 - 根据树形进行LL、RR、LR、RL旋转调整

    删除调整¶

    红黑树删除的复杂性

    红黑树的删除操作较为复杂，需要根据被删结点的颜色、兄弟结点的颜色及其子结点情况，结合变色和旋转进行多种调整。

    • 被删结点为红色叶子：直接删除，无需调整。
    • 被删结点为黑色叶子：产生“双黑”问题，需要调整。
    • 被删结点有一个孩子：用子结点替代被删结点，并将其染黑。
    • 被删结点有两个孩子：用中序后继（或前驱）替换后，转化为前两种情况。

    双黑调整的主要情形：

    1. 兄弟结点为黑色，且至少有一个红孩子：
      • 通过旋转和变色消除双黑，具体分为四种情况（LL、RR、LR、RL）：
        • LL型：兄弟的左孩子为红色，右旋父结点，兄弟变父色，父变黑，兄弟左孩子变黑，双黑消除。
        • RR型：兄弟的右孩子为红色，左旋父结点，兄弟变父色，父变黑，兄弟右孩子变黑，双黑消除。
        • LR型：兄弟的右孩子为红色，先左旋兄弟，再右旋父结点，调整颜色，双黑消除。
        • RL型：兄弟的左孩子为红色，先右旋兄弟，再左旋父结点，调整颜色，双黑消除。

    1. 兄弟结点为黑色，且两个孩子都是黑色：

      • 兄弟变红，双黑上移到父结点，继续调整，直到遇到红色父结点或根结点（将其变黑）。

    2. 兄弟结点为红色：

      • 兄弟与父结点变色，朝双黑方向旋转，使兄弟变为黑色，再按上述情况继续调整。

    7.3 多路查找树¶

    7.3.1 B树¶

    B树的特点

    • 多路平衡搜索树：适合磁盘存储
    • 结点访问：结点存储在磁盘，结点内操作在内存
    • 平衡性：所有叶结点在同一层

    m阶B树的性质

    • 根结点：至少2个分支，1个元素
    • 其他结点：至少⌈m/2⌉个分支，⌈m/2⌉-1个元素
    • 有序性：结点内元素有序，子树间关系有序
    B树操作¶

    B树的基本操作

    查找：从根开始，结点内二分查找，失败结点存在

    插入： 1. 查找插入位置 2. 若结点上溢（元素数≥m），进行分裂 3. 中间元素上移，两边分别成为新结点 4. 分裂可能向上传播

    删除： 1. 非叶结点删除转化为叶结点删除 2. 若删除后低于下限： - 尝试向兄弟借元素（父结点下移，兄弟元素上移） - 无法借用时合并（父元素下移，左右合并）

    7.3.2 B+树¶

    B+树的改进

    • 叶结点链接：按大小顺序链接所有叶结点
    • 多级索引：非叶结点仅作索引，叶结点包含所有数据
    • 结点结构：m个分支对应m个元素

    B+树的优势

    适合顺序查找、随机查找和范围查找

    7.4 散列表（Hash Table）¶

    7.4.1 散列函数¶

    常用散列函数

    直接定址法：H(key) = a×key + b - 适合关键字分布连续的情况

    除留余数法：H(key) = key % p - p通常选择小于等于表长的最大质数

    装填因子

    α = n/m（n为元素个数，m为表长）

    装填因子影响散列表的性能，α越大冲突越多。

    7.4.2 冲突处理¶

    开放定址法¶

    开放定址法的两种策略

    线性探测法： - 冲突时检查下一个位置：H(key) + i - 构建完成后可用于查找，遇到空位置表示查找失败

    平方探测法： - 探测序列：+1², -1², +2², -2², ... - 可以减少聚集现象

    拉链法¶

    拉链法（链地址法）

    • 实现：散列表每个位置维护一个链表
    • 插入：通常使用头插法
    • 优势：处理冲突简单，删除方便

    7.4.3 性能分析¶

    散列表性能计算

    ASL计算： - 成功查找：插入时累加比较次数求平均 - 失败查找：各位置查找失败的平均次数

    删除操作：通常打标记为DEL，不影响查找过程

    ch8. 排序¶

    排序算法概述

    排序是将一序列对象按某种逻辑顺序重新排列的过程，是数据处理中的基本操作。

    8.1 排序算法分类¶

    排序算法记忆口诀

    插冒龟很稳，选堆插很方，快归队n老，基稳

    • 稳定排序：插入、冒泡、归并、基数
    • 不稳定排序：选择、堆排序、快速排序、希尔

    8.2 排序算法复杂度对比¶

    排序算法性能对比表

    算法名称 最好情况 平均情况 最坏情况 空间复杂度 是否稳定 特点
    直接插入排序 O(n) O(n²) O(n²) O(1) 是 适合小规模数据
    冒泡排序 O(n) O(n²) O(n²) O(1) 是 简单但效率低
    简单选择排序 O(n²) O(n²) O(n²) O(1) 否 交换次数少
    希尔排序 O(n) O(n^1.3) O(n²) O(1) 否 插入排序改进
    快速排序 O(nlog₂n) O(nlog₂n) O(n²) O(log₂n) 否 平均性能最佳
    堆排序 O(nlog₂n) O(nlog₂n) O(nlog₂n) O(1) 否 稳定O(nlogn)
    归并排序 O(nlog₂n) O(nlog₂n) O(nlog₂n) O(n) 是 稳定O(nlogn)
    基数排序 O(d(n+r)) O(d(n+r)) O(d(n+r)) O(r) 是 非比较排序

    算法选择建议

    小规模数据（n<50）：直接插入排序

    中等规模数据：快速排序（平均情况最佳）

    要求稳定性：归并排序

    内存受限：堆排序（原地排序）

    特殊数据类型：基数排序（整数、字符串）

    8.3 排序算法的稳定性¶

    稳定性的意义

    稳定排序：相等元素的相对顺序在排序前后保持不变

    应用价值：在多关键字排序中，稳定性能保证次要关键字的有序性

    排序算法总结

    • 时间复杂度：O(nlogn)是基于比较的排序算法的理论下界
    • 空间复杂度：原地排序算法空间复杂度为O(1)
    • 实际应用：需要根据数据规模、稳定性要求、内存限制等因素综合选择
